## 2. Что уже работает [ФАКТ]

1. Безопасный вход: один webhook, secret_token, белый список владельца, внутренние вебхуки с `internal_token`.
2. Дедупликация: нормализация URL (utm, fbclid и др.), sha256 URL и текста, ключ `fl-<id>` в источнике.
3. Analyst выдаёт строгий JSON, Make его проверяет; score считает Make по весам из настроек; есть жёсткие ограничения
   (нет ссылки ≤59, риск ≤39, бюджет ниже минимума ≤59, prospect ≤59).
4. Бюджет на AI в день (`daily_budget_usd` = 3 $), автопауза, очередь при паузе, `/resume` разбирает очередь.
5. Architect + Sales: ТЗ, 3 пакета цен, сообщение клиенту на его языке и по-русски, проверка цен и полей.
6. Воронка статусов до WON/LOST с причинами, `/stats` за 7 и 30 дней.
7. Генератор сценариев (`scripts/generate_lh.py`) и эталон скоринга с тестами (`scripts/scoring.py`) — воспроизводимая сборка.

## 4. Рекомендуемая логика `/search_settings`

### 4.1 Модель данных — новая запись `search` в lh_settings (207951)

```json
{
  "enabled_sources": ["freelancer"],
  "categories": ["telegram_bot", "chatbot", "make_automation", "mini_app"],
  "category_map": {
    "telegram_bot": [/* ID навыков Freelancer — проверить через /api/projects/0.1/jobs/?job_names[]=... */],
    "chatbot": [],
    "make_automation": [],
    "mini_app": []
  },
  "include_keywords": ["telegram", "bot", "chatbot", "mini app", "make.com", "automation"],
  "exclude_keywords": ["translation", "translator", "garment", "instructor", "data entry", "chat admin"],
  "countries": ["DE", "AT", "CH"],
  "languages": ["de", "en", "ru"],
  "budget_fixed_min_eur": 300,
  "budget_hourly_min_eur": 15,
  "max_bids": 40,
  "window_hours": 12,
  "max_per_run": 5,
  "send_grades": ["HOT", "WARM"],
  "updated_at": "…",
  "version": 1
}
```

### 4.2 Интерфейс в Telegram (LH-20)

- `/search_settings` — показать текущие значения и inline-кнопки: **Категории · Страны · Языки · Бюджет · Источники · Что слать · Сброс**.
- Переключатели категорий, стран и языков: callback `ss|cat|telegram_bot` и т. п. Нажатие включает или выключает значение,
  сообщение редактируется (`editMessageText`) с отметками ✅.
- Бюджет: кнопки-пресеты (`ss|bfix|300`, `500`, `1000`) и текстовая форма
  `/search_settings budget 500` или `/search_settings hourly 20`.
- Валидация в Make: только ключи из белого списка, коды стран ISO-2, языков ISO-639-1, числа в диапазоне;
  иначе — ответ с ошибкой, ничего не записывается.
- Каждое изменение — событие `SEARCH_SETTINGS_CHANGED` в lh_log (старое → новое), `version + 1`. Кнопка «↩️ Откатить» возвращает предыдущую версию.
- Доступ только владельцу: та же проверка secret_token и chat_id, что для остальных команд.

### 4.3 Как настройки применяются

1. 7744024 в начале читает `search` и собирает URL Freelancer из `category_map[categories]`, `window_hours` и `limit`.
   [ПРЕДПОЛОЖЕНИЕ] Freelancer API поддерживает `languages[]` и, возможно, `countries[]` у `projects/active`. До проверки
   страну и язык фильтровать в Make после ответа API (поле `language` есть в ответе; страна — через `owner`/`users` при `user_details=true`, проверить).
2. Детерминированный предфильтр в Make (без AI): ключевые слова include/exclude по title+description, бюджет, `bid_count ≤ max_bids`.
   Отсеянное — запись в источник со статусом `filtered_out` и причиной, в LH-03 не идёт.
3. LH-10: карточку в Telegram слать только для `send_grades`; остальное — в архив без сообщения (видно в `/today` и `/stats`).
4. Analyst получает блок «SEARCH FOCUS» (целевые страны, языки, категории), чтобы `fit` учитывал выбранное направление.

## 6. Инструкция для ChatGPT: конкретные действия по улучшению сценариев Make

> Ты помогаешь владельцу улучшить сценарии Make (eu1, команда 2241615) для Lead Hunter.
> **Правила:**
> - Не удаляй сценарии и данные.
> - Перед каждым изменением экспортируй блюпринт (Make → сценарий → ⋯ → Export Blueprint) и сохрани его.
> - Секреты (токены, ключи, chat_id) никогда не пиши в чат и не вставляй в промты — только через подключения Make.
> - Клиентам ничего не отправлять автоматически.
> - Меняй по одному сценарию. После изменения — 1 тестовый запуск (Run once) и проверка истории выполнения.

**Шаг 1. Проверить ID категорий Freelancer.**
Сделай в Make временный сценарий: HTTP GET `https://www.freelancer.com/api/projects/0.1/jobs/?job_names[]=Telegram%20API&job_names[]=Chatbot&job_names[]=Make.com&job_names[]=Bot%20Development`.
Выпиши `id` и `name` из ответа. Сравни с текущими `jobs[]` в модуле 2 сценария 7744024 (2380, 2068, 2918, 2917, 2823). Сценарий потом выключи.

**Шаг 2. Предфильтр в 7744024 (до передачи в LH-03).** После модуля 3 (Iterator по `projects`) и до модуля 6 добавь фильтр на связи:
- `lower(title + " " + preview_description)` содержит хотя бы одно из include-слов (`telegram`, `bot`, `chatbot`, `mini app`, `make.com`) — условия через OR;
- и не содержит ни одного exclude-слова (`translat`, `garment`, `instructor`, `data entry`, `chat admin`, `virtual assistant`) — условия через AND с оператором «Does not contain»;
- и `bid_stats.bid_count` ≤ 40.

Отсеянные можно (по желанию) писать в Data Store 205357 со `status = filtered_out` и причиной — отдельный маршрут Router.

**Шаг 3. Вынести параметры в настройки.** В Data Store `lh_settings (207951)` создай запись с ключом `search`:
поля как в разделе 4.1 отчёта. В 7744024 добавь первым модулем `Data store → Get a record (key = search)`.
URL модуля HTTP собери из настроек: `jobs[]` из `join(map(...); "&jobs[]=")`, `from_time` из `window_hours`.
Бюджеты в фильтре модуля 6 замени на `search.budget_fixed_min_eur` и `search.budget_hourly_min_eur`; лимит за запуск — на `search.max_per_run`.

**Шаг 4. Не слать REJECT в Telegram (LH-10).** На маршруте отправки карточки добавь условие `grade` ∈ `search.send_grades`
(по умолчанию HOT, WARM). Для остальных — только обновить статус лида на `ARCHIVED` и записать событие в lh_log.

**Шаг 5. Команда `/search_settings` в LH-20.**
- В Router сценария LH-20 добавь маршрут с фильтром `cmd = /search_settings`.
  Он читает `search` и отправляет `sendMessage` с текущими значениями и `reply_markup` (inline-клавиатура).
  `callback_data` в формате `ss|<поле>|<значение>` — до 64 байт.
- Второй маршрут — фильтр `callback_data` начинается с `ss|`:
  1. разобрать `split(data; "|")`;
  2. проверить поле по белому списку (`cat`, `country`, `lang`, `bfix`, `bhour`, `grades`, `reset`, `undo`);
  3. переключить значение в массиве;
  4. перед записью сохранить старую версию в `search_prev`;
  5. записать `search` с `version + 1`;
  6. записать событие `SEARCH_SETTINGS_CHANGED` в lh_log;
  7. `editMessageText` с обновлёнными ✅;
  8. `answerCallbackQuery`.
- Третий маршрут — текстовая форма `/search_settings budget 500`: разобрать аргументы и проверить число (50–100 000).
- Проверка владельца (secret_token и chat_id) уже есть в начале LH-20 — новые маршруты ставь после неё.
- Важно: LH-20 собирается генератором `lead-hunter/scripts/generate_lh.py` и весит больше 100 КБ. Изменения лучше вносить
  в генератор (функция `lh20()`), а не руками в редакторе, затем импортировать JSON в сценарий 7789394 вручную (Import Blueprint).
