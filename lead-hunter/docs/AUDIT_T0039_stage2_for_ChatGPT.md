## E. Целевая архитектура DIRECTOR и SYSTEM GUARDIAN

### E.1 DIRECTOR — минимальные изменения
Новых LLM-агентов не нужно. DIRECTOR — это два уровня.

1. **Runtime-DIRECTOR в Make** — новый сценарий **LH-30 Director Gate** (детерминированный, без LLM), вызывается после каждого агента:
   - проверяет полноту результата: обязательные поля, JSON валиден, перевод есть, категория из `search.categories`;
   - решает, что дальше: следующий агент, архив с причиной, «🔍 ещё анализ», карточка владельцу;
   - пишет в `lh_log` событие `DIRECTOR_DECISION` (lead_id, этап, решение, причина);
   - назначает «ответственного» через поле `stage_owner` (analyst / architect / sales / estimator / owner / executor).

   Существующие LH-10 и LH-11 остаются. Меняется только то, куда они отдают результат: в LH-30, а не сразу в Telegram.
2. **Claude-DIRECTOR (уже есть)** — раз в день по Make API и `lh_leads` проверяет:

**Расчёт прибыли (Estimator)** — модуль в LH-30 после Sales, только формулы, без AI:
