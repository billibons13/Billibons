## 2. Целевая логика: «организация» обрабатывает пакет и приходит к владельцу с решениями

### 2.1 Жизненный цикл пакета

```
① СБОР            Scout (LH-01 + второй источник) → Gatekeeper → LH-03: лиды NEW
② ПРЕДАНАЛИЗ      Analyst (LH-10, режим batch): анализ без отправки в Telegram → статус BATCH_QUEUED
③ ЗАКРЫТИЕ ПАКЕТА DIRECTOR (LH-12 Batch Builder, по расписанию): пакет закрывается, когда
                  набралось ≥ 15 лидов ИЛИ прошло 48 ч и есть ≥ 5 лидов (чтобы не ждать бесконечно);
                  максимум 20 — остальные уходят в следующий пакет
④ ПРОМЕЖУТОЧНЫЙ   DIRECTOR (Claude, 1 вызов на пакет): сравнивает лиды между собой → ранжирует,
   АНАЛИЗ         отмечает дубли и похожие запросы, даёт топ-5 с причинами, «быстрые отказы», вопросы владельцу
⑤ ЭКОНОМИКА       Estimator (формулы Make) для топ-5: грубая прибыль по часам Analyst (без Architect — дёшево)
⑥ TELEGRAM        1 сводка пакета + карточки топ-5 с 6 кнопками; остальные — по кнопке «📋 Весь пакет»
⑦ РЕШЕНИЯ         владелец: ✅ / ❌ / 🔁 / ✏️ / 📄 / 📋 → журнал decisions (lead_id + batch_id + chat_id)
⑧ ГЛУБОКАЯ        только для ✅: Architect + Sales + Estimator (LH-11) → карточка 2 → ✅ «В работу»
   ПРОРАБОТКА     → задачи исполнителям (LH-31, этап 9 плана) — без обязательств перед заказчиком
⑨ ИТОГ ПАКЕТА     DIRECTOR: отчёт «пакет №N: 18 лидов → 5 показано → 2 согласовано → …» + уроки для обучения
```

### 2.2 Кто что делает (RACI по пакету)

R — выполняет, A — отвечает, C — консультирует, I — получает информацию.

| Шаг | Scout | Gatekeeper | Analyst | DIRECTOR | Architect | Sales | Estimator | GUARDIAN | Владелец |
|---|---|---|---|---|---|---|---|---|---|
| ① Сбор | R | R | | A | | | | I (пульс) | |
| ② Предварительный анализ | | | R | A | | | | I (ошибки) | |
| ③ Закрытие пакета | | | | R/A | | | | I | |
| ④ Ранжирование и сравнение | | | C | R/A | | | | | |
| ⑤ Грубая экономика топ-5 | | | C | A | | | R | | |
| ⑥ Сводка и карточки | | | | R/A | | | | I (доставка) | I |
| ⑦ Решение | | | | C | | | | | **A (единственный)** |
| ⑧ ТЗ, КП, прибыль | | | | A | R | R | R | I | I |
| ⑨ Итог и уроки | | | | R/A | | | | | I |

Принципы распределения:
- DIRECTOR **не делает чужую работу**: он назначает, проверяет полноту и сводит.
- Решения о деньгах, цене и клиенте принимает только владелец.
- GUARDIAN следит, чтобы пакет не завис: пакет не закрылся за 72 ч, Analyst упал, карточка не доставлена.

### 2.3 Статусы лида (добавляются, существующие не меняются)

`NEW → BATCH_QUEUED → IN_BATCH(batch_id) → SHOWN | BATCH_ARCHIVED → APPROVED → TECHNICAL_SPEC_READY → IN_EXECUTION → WON/LOST`
+ существующие `REJECTED`, `ERROR`, `ARCHIVED`.

Новое хранилище **`lh_batches`**: batch_id, opened_at, closed_at, lead_ids, top_ids, summary_text, director_json, tg_message_id, status (OPEN / CLOSED / SENT / DONE), counts.

```
Отсеяно сразу: 11 (мусор 6, бюджет < 100 € 3, дубли 2) · расход AI: 0,4 $ / ~210 кредитов

🏆 Топ-5 (подробно ниже):
1. 🔥 HOT 84 · Telegram-магазин для кофейни (DE) · 1 200 € · прибыль ≈ 640 € · 🟢 GO
2. 🌤 WARM 72 · Make: CRM + счета (UK) · 900 € · ≈ 410 € · 🟢 GO
3. …
❓ Директору нужно ваше мнение: 2 похожих запроса на AI-ассистента — объединить предложение?
[📋 Весь пакет] [❌ Отклонить остальные] [📋 Мои задачи]
```

### 3.2 Карточка лида (топ-5)
```
🔥 HOT 84 · №7-1 · LH-20261014-a1b2c3
📌 Telegram-магазин для кофейни · 🇩🇪 de → перевод ru · удалённо ✅
💰 Бюджет клиента 1 200 € (не прибыль) · комиссия площадки 10 % · исполнители ≈ 420 € · прибыль ≈ 640 € (53 %) 🟢
🧠 Суть: … · Что важно клиенту: … · Риски: … · Соответствие нам: высокое (готовая база e-commerce)
🧭 Директор: «Берём: 1 из 3 лучших в пакете, похожий проект уже сделан»
[✅ Согласовать] [❌ Отклонить]
[🔁 Доработать] [✏️ Изменить условия]
[📄 Подробнее] [📋 Мои задачи]
```

### 3.3 Что делает каждая кнопка

| Кнопка | callback_data (≤ 64 байт) | Действие | Защита от дублей | Журнал |
|---|---|---|---|---|
| ✅ Согласовать | `ap|<lead_id>` (есть) | запуск Architect + Sales + Estimator (LH-11) → карточка 2; на карточке 2 «Согласовать» = `ex|<lead_id>` → «В работу» | есть `architect_run_id`; для `ex` — новый `execution_run_id` | `decisions: APPROVE` / `EXECUTE` + batch_id |
| ❌ Отклонить | `rj|<lead_id>` (есть) → 5 причин + «✍️ своя» | статус REJECTED | повторное нажатие → «уже отклонён» | `decisions: REJECT` + reason |
| 🔁 Доработать | `rw|<lead_id>` (новое) | бот спрашивает «что уточнить?» → текст владельца → повторный анализ с комментарием (1 раз бесплатно, дальше — с подтверждением расхода) | `rework_count` | `decisions: REWORK` + comment |
| ✏️ Изменить условия | `cc|<lead_id>` (новое) | «цена / срок / объём?» → текст «цена 800, срок 3 недели» → Sales + Estimator пересчитывают → новая карточка | версия КП `offer_v` | `decisions: CHANGE_TERMS` + diff |
| 📄 Подробнее | `dt|<lead_id>` (новое; после LH-11 есть 📋 💰 💬 ❓) | полный разбор Analyst: 10 оценок, вопросы клиенту, оригинал и перевод | только чтение | — |
| 📋 Мои задачи | `mt|` (новое) + команда `/tasks` | ваша очередь: ждут решения (по пакетам), в работе, просроченные | только чтение | — |
| 📋 Весь пакет | `bl|<batch_id>|<page>` | список всех лидов пакета по 5, у каждого кнопки ✅ ❌ 📄 | только чтение | — |
| ❌ Отклонить остальные | `bx|<batch_id>` → подтверждение «Да, отклонить 13» | массовый отказ с причиной «не в топе» | подтверждение + статус пакета | `decisions: BULK_REJECT` |

Общие правила:
- Каждое нажатие сначала проверяет chat_id владельца (уже есть в LH-20).
- Каждое решение пишется в `lh_log.decisions`: `lead_id`, `batch_id`, `owner_chat_id`, `telegram_message_id`, `action`, `reason` / `comment`, `created_at`. Это данные для обучения на ваших решениях.
- **Никакая кнопка не отправляет ничего заказчику и не создаёт обязательств.** Отправить сообщение клиенту, подать ставку, принять заказ, заплатить — отдельное действие владельца вне бота или отдельная кнопка с подтверждением (этап 9 плана, только после вашего согласия на её создание).

## 4. Промпты

### 4.1 Промпт агента DIRECTOR для пакета (Claude Sonnet, 1 вызов на пакет)
```
You are DIRECTOR — the coordinator of a small autonomous studio team (Scout, Gatekeeper, Analyst, Architect, Sales,
Estimator, GUARDIAN). You review ONE batch of 5–20 pre-analyzed commercial leads and prepare decisions for the owner.
The owner alone decides. You never contact clients, never commit to anything, never change prices or limits.

Input: JSON {batch_id, leads:[{lead_id, title, category, language, country, remote_ok, budget_eur, budget_type,
grade, score, scores{10}, reasons, risk_flags, authenticity_flags, capability_fit, description_ru, est_hours_min,
est_hours_max}], settings:{min_budget_eur, categories, internal_rate_eur, platform_fee_pct}}.

Do:
1. Compare leads WITH EACH OTHER (not only absolute score): pick TOP up to 5 by expected profit × win probability ×
   capability fit. A lead with risk_flags can be in TOP only with an explicit reason.
2. Detect duplicates / near-identical requests (same client or same task) → group them.
3. Quick rejects: list lead_ids that are clearly not ours with a 3–6 word reason each.
4. For each TOP lead: one-line recommendation in Russian ("Берём, потому что…" / "Проверить: …"), the single most
   important open question for the client, and the main risk.
5. Up to 2 questions for the owner where the batch reveals a pattern (e.g. many similar requests, prices too low).

Rules: use only data from input; unknown → "UNKNOWN"; never invent budgets, clients or deadlines; budget ≠ profit.
Output ONLY JSON:
{"batch_id":"…","top":[{"lead_id":"…","rank":1,"recommendation_ru":"…","client_question_ru":"…","main_risk_ru":"…"}],
 "groups":[{"lead_ids":["…"],"note_ru":"…"}],"quick_rejects":[{"lead_id":"…","reason_ru":"…"}],
 "owner_questions_ru":["…"],"batch_summary_ru":"≤ 300 символов"}
Self-check before answering: every lead_id exists in input; top ≤ 5; no lead both in top and quick_rejects; valid JSON.
```

## 6. Что нужно решить вам перед внедрением
1. Размер пакета и сроки: 15–20 лидов или 48 ч (не меньше 5 лидов) — подходит?
2. Топ-5 подробно, остальные по кнопке — или показывать все карточки сразу?
3. «Согласовать» в пакете = запуск полной проработки (ТЗ/КП, ≈ 150 кредитов на лид), а «В работу» — отдельной кнопкой на карточке 2. Подходит?
4. Бюджет кредитов на пакетную обработку до 30.10 (рекомендую не больше 1 пакета в 3–4 дня до подключения своего ключа Anthropic).
5. Ставка исполнителей и комиссия площадки для грубой экономики — или пока показывать «прибыль: UNKNOWN, нужна ставка»?
6. Одобрение шагов 1–10 по одному или блоками (1–6, затем 7–10).
