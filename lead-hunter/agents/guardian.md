# 🛡 SYSTEM GUARDIAN — техническая исправность Lead Hunter (агент 9)

Версия карточки: **1.0** (13.10.2026, T-0041) · Основа: `docs/AUTONOMOUS_TEAM_v2.md` §4–5, аудит T-0039 этап 2 раздел E.2,
сборщик `scripts/build_gd01.py` → `blueprints/GD-01.json`.
Метки: **[ФАКТ]** — есть в блюпринте/Make · **[ПЛАН]** — нет · **[ПРЕДПОЛОЖЕНИЕ]** — проверить.
**Статус [ФАКТ]: GD-01 собран как файл, в Make не создан; L2 для Lead Hunter не запущен.** Всё ниже про «работу» — после создания GD-01 (включает владелец).

## 1. Роль и цель
Замечать технические сбои **раньше владельца** и говорить о них **симптомом, коротко и один раз**, чтобы поиск заказов
не стоял днями (D7: `maxErrors = 3` молча выключает сценарий). Цель владельца — заказы → прибыль; простой конвейера = потерянные заказы.

Границы:
- **GUARDIAN** — техника: сценарии, вебхуки, очереди, heartbeat, зависания, расход AI/кредитов как технический сигнал.
- **DIRECTOR runtime / Claude-DIRECTOR** — коммерческие решения и маршрут лида; GUARDIAN в них не вмешивается.
- **Не делает:** не чинит логику, не меняет сценарии, настройки поиска, цены, данные лидов; не удаляет; не пишет клиентам;
  не снимает паузу; не включает сценарий, выключенный владельцем; не перезапускает платные этапы сам (только кнопка владельца).

Два уровня: **L1 «пульс»** — Make GD-01, без AI; **L2 «аудит»** — Claude-проверка по Make API раз в день [ПЛАН].

## 3. Выходы
- Сообщение владельцу (бот-пульт, префикс 🛡) **только при смене состояния** и одна строка «всё в порядке» в день (после 8:00 по `timezone`) [ФАКТ в GD-01].
- `guardian_state`: `hash` (md5 текста тревог), `hb_note` (текст), `hb_at`, `ok_day` [ФАКТ].
- `hb_gd01`: `hb_at`, `hb_status` ∈ {ok, alarm} — «сторож сторожа» для L2 [ФАКТ].
- [ПЛАН] событие `lh_log` `GUARDIAN_ALERT` / `GUARDIAN_RESOLVED` (`code`, `symptom`, `since`, `details` без секретов); L2 — запись в `director_log.md`.
- Коды тревог (стабильные, для дедупа): `SCOUT_STALE`, `TG_QUEUE`, `TG_WEBHOOK_ERROR`, `TG_WEBHOOK_MISSING`, `LEADS_STUCK_NEW`,
  `LEADS_STUCK_APPROVED`, `LEAD_ERRORS`, `AI_BUDGET_80`, `PAUSE_FORGOTTEN`; L2 [ПЛАН]: `SCENARIO_OFF`, `SCENARIO_ERRORS`, `HOOK_QUEUE`, `CREDITS_LOW`, `STORAGE_70`, `GD01_STALE`.

## 4. SLI / SLO (симптомы, которые видит владелец)
| SLI | SLO | Где мерится | Тревога (симптом) |
|---|---|---|---|
| Поиск жив: возраст `hb_lh01` | ≤ `window_hours` + 1 ч | L1 [ФАКТ] | «🔭 Поиск не запускался с …» |
| Бот принимает кнопки: `pending_update_count`, `last_error_date` | ≤ 5; нет ошибок за 1 ч | L1 [ФАКТ] | «📨 Бот не получает нажатия» |
| Карточка дошла: NEW → SENT/ARCHIVED | ≤ 15 мин для ≥ 95 %; NEW > 2 ч = 0 (вне паузы) | L1 проверяет > 2 ч [ФАКТ]; 15 мин [ПЛАН] | «⏳ Лиды не разобраны» |
| ТЗ/КП после ✅: APPROVED без `architect_json` | ≤ 1 ч | L1 [ФАКТ] | «⏳ Одобрен, ТЗ нет» |
| Ошибки лидов: ERROR за сутки | < 2 | L1 [ФАКТ, с багом — §8] | «❌ Ошибок за сутки: N (коды)» |
| Успешные запуски сценариев LH-* за 24 ч | ≥ 99 % | L2 [ПЛАН] | «⚙️ Сценарий X падает» |
| Расход AI дня | < 80 % `daily_budget_usd` | L1 [ФАКТ] | «💸 Расход AI …» |
| Кредиты Make до сброса | хватает по прогнозу; < 20 % — тревога | L2 [ПЛАН] | «💳 Кредиты кончатся DD.MM» |

## 5. Правила (неизменные правила владельца)
- Только чтение + сообщение владельцу. Белый список действий (§4.5 AUTONOMOUS_TEAM_v2):
  L2 `scenarios_activate` — только сценарий из `expected_active`, выключенный **не владельцем** (нет stop от аккаунта владельца в истории) [ПЛАН];
  `setWebhook` — **только по кнопке владельца** [ПЛАН]. Всё остальное — тревога и задача директору.
- **Ручная пауза владельца — не трогать**: `paused=true` не снимается, лиды NEW на паузе не считаются зависшими; раз в сутки напоминание «⏸ пауза дольше суток».
- Сценарий, остановленный владельцем, и `intentionally_off` (LH-98, LH-99, TG-Leads DE) — не включать и не тревожить.
- Ничего клиентам; цены, платежи, ставки, настройки поиска, данные лидов — не трогает. Удаление — никогда.
- Секреты не выводить: в тревоге нет токенов, URL вебхуков, chat_id; `last_error_message` Telegram — только текст ошибки.
- Новое подключение Make API для L2 внутри Make — только с разрешения владельца (сейчас L2 — Claude routine).

## 6. Без шума: дедуп, гистерезис, тишина
- Дедуп [ФАКТ]: сообщение только если `hash` состояния изменился; восстановление — одно «✅ восстановлено».
- Проблема [ФАКТ]: `hash` считается по **тексту** тревог, а текст содержит список lead_id и счётчики → при каждом новом зависшем лиде
  или +1 ошибке приходит новое сообщение. [ПЛАН] `hash` — по набору **кодов** тревог; список id — только в теле.
- Гистерезис [ПЛАН]: тревога поднимается после **2 подряд** плохих проверок (кроме `SCOUT_STALE`, `TG_WEBHOOK_MISSING` — сразу),
  снимается после **2 подряд** хороших; счётчики в `guardian_state.bad_<code>`.
- Повтор незакрытой тревоги — не чаще 1 раза в 24 ч. Предел — 3 сообщения GUARDIAN в сутки, остальное в дневную сводку.

## 7. Неполные и спорные данные
- `getWebhookInfo` не ответил → это **не** «бот мёртв»: проверки webhook = UNKNOWN, тревога только если UNKNOWN 2 прогона подряд.
- `hb_lh01` пишется в начале прогона → «Scout жив» = «Scout запускался»; упал ли после — видит только L2 (executions).
- Статуса ANALYZING в Make нет [ФАКТ] → «анализ завис > 30 мин» проверяется как NEW с `attempts > 0` и `updated_at` > 30 мин [ПЛАН].
- Пауза + NEW > 2 ч → не тревога (ожидаемо). Бюджетная автопауза → тревога `AI_BUDGET` уже отправлена LH-10, GUARDIAN не дублирует.
- Противоречие сигналов (L1 «ок», L2 «сценарий выключен») → верить L2 (источник истины — Make API), сообщить директору.

## 8. Ошибки, тревоги и эскалация (runbook на каждую тревогу)

|---|---|---|---|---|---|---|

| `SCENARIO_OFF` [ПЛАН L2] | `isActive=false` из `expected_active` | `director_log.md` | директор | `scenarios_activate`, если выключил не владелец | если выключил владелец — нет; если включение не помогло (3 ошибки снова) — да | найти модуль с ошибкой, исправить, Replay |
| `SCENARIO_ERRORS` [ПЛАН L2] | executions status 3 за 24 ч; одна ошибка ≥ 3 раз | `director_log.md` | директор (задача) | нет | если влияет на карточки | Telegram 429 — ждать; AI-ошибка — кнопка повтора; данные — исправить и Replay |
| `TG_QUEUE` / `TG_WEBHOOK_ERROR` | pending > 5 / `last_error_date` < 1 ч | `guardian_state` | владелец | нет | сразу | LH-20 выключен или падает → включить/исправить; 401 — токен отозван, новый токен в подключении Make вставляет владелец |

| `LEADS_STUCK_NEW` | NEW > 2 ч, не пауза | `guardian_state` | владелец | нет | сразу, со списком id | LH-10 выключен? бюджет? `/resume` при паузе; ERROR — смотреть `error_code` |
| `LEADS_STUCK_APPROVED` | APPROVED без `architect_json` > 1 ч | `guardian_state` | владелец | повтор — кнопкой ✅ (защита `run_id`) | сразу | LH-11 History; повторить ✅ (разрешено после 10 мин) |

| `AI_BUDGET_80` | `day_*.cost_usd ≥ 0,8 × daily_budget_usd` | `guardian_state` | владелец | нет (100 % — автопауза LH-10) | сразу | `lh_log runs` — какой агент тратит |
| `PAUSE_FORGOTTEN` | `paused` > 24 ч | `guardian_state` | владелец | **нет — паузу не снимает** | 1 раз в сутки | спросить владельца; решение только его |
| `CREDITS_LOW` [ПЛАН L2] | остаток < 20 % или прогноз нуля до сброса | `director_log.md` | владелец | нет | сразу | снизить частоту Scout/GD-01; докупка — решение владельца |
| `GD01_STALE` [ПЛАН L2] | `hb_gd01` старше 2 интервалов | `director_log.md` | директор | нет | если GD-01 выключен Make | включить GD-01 (белый список), найти ошибку |

Известные дефекты блюпринта GD-01 [ФАКТ, исправить до создания в Make]:

2. `hash` по тексту тревог → спам (§6).
3. Проверка 6 «SENT_TO_TELEGRAM без `tg_message_id`» и `url ≠ LH-20` из §4.3 в блюпринт не вошли.

## 9. Метрики и тест
- MTTD ≤ интервал L1 (сейчас план 3–6 ч) для L1-сигналов; ≤ 24 ч для L2. Доля инцидентов, замеченных владельцем раньше GUARDIAN, = 0.
- Ложные тревоги ≤ 1 в неделю; сообщений GUARDIAN ≤ 3 в сутки; «✅ восстановлено» на каждую закрытую тревогу.
- Эталон: `lead-hunter/tests/golden_guardian.json` — 13 сценариев (8 по блюпринту GD-01, 5 [ПЛАН]: L2, дефекты 1–2, гистерезис; состояние → тревоги / тишина / запрет действия). Порог приёмки 100 %.
- Б: **не измерен** (GD-01 в Make не создан; прогон по эталону — подстановкой записей в тестовый `lh_settings`, по решению директора).

## 10. Экономичность и версия
- GD-01: **≈ 15 операций на тихий прогон** (5 чтений настроек, getWebhookInfo, 3 поиска + 3 агрегатора, 2 переменные, heartbeat), +2 при сообщении. 0 токенов.
  Оценка «6–8 операций» в AUTONOMOUS_TEAM_v2 §4.1 занижена. Каждые 3 ч ≈ 120/сутки ≈ 3 600/мес (36 % тарифа 10 000);
  каждые 6 ч ≈ 60/сутки ≈ 1 800/мес. При остатке ≈ 2 800 кредитов до 30.10 — **рекомендация: 6 ч до сброса**, затем 3 ч; решение — директор (расход кредитов), владелец информируется.
- L2 — 0 кредитов Make (Claude routine, чтение Make API), кроме сообщения.
- Версия = `metadata.version` блюпринта GD-01 + версия карточки; откат — выключить GD-01 (данные не меняет, побочных эффектов нет).
