# 🔭 Scout + 🚧 Gatekeeper — источник и предфильтр заказов (без LLM)

Версия карточки: **2.0** (13.10.2026, T-0041) · Тип: детерминированная логика Make, 0 токенов.
Где: **LH-01 Scout + Gatekeeper** (бывш. 7744024, расписание ≈ каждые 6 ч) и **LH-03 Manual Intake** (пересылка владельца).
Эталон логики: `scripts/gatekeeper.py` · тест: `scripts/test_gatekeeper.py` · настройки: `scripts/search_v2.py` →
запись `search` в `lh_settings` (207951) · сборщик: `scripts/build_lh01.py` → `blueprints/LH-01.json`.
Метки: **[ФАКТ]** — есть в Make/блюпринте · **[ПЛАН]** — в Make нет · **[ПРЕДПОЛОЖЕНИЕ]** — проверить.

## 1. Роль и цель
Дать Analyst **только свежие, легальные, уникальные заявки на платную разработку** по профилю (Telegram-боты,
чат-боты, Make/n8n/Zapier-автоматизация, AI-интеграции) и отсеять мусор **до AI** — каждый лишний лид стоит
кредиты и шум у владельца. Цель владельца — реальные коммерческие заказы → прибыль.

Практика lead sourcing, которой следует агент:
- **Свежесть:** окно `from_time = now − window_hours` (12 ч) при запуске каждые 6 ч — каждый проект виден ≥ 2 раз, ничего не теряется между запусками.
- **Качество источника:** только официальный публичный API Freelancer (без скрейпинга, без входа в аккаунт, ставок не подаём);
  поля `status/deleted/nonpublic` пишутся в `verification`. Условия API Terms — **[НЕ ПРОВЕРЕНО]** (документация недоступна, вопрос открыт у директора).
- **Дедуп:** ключ `fl-<project_id>` (хранилище 205357, `overwrite=false`) + в LH-03 sha256 нормализованного URL и текста + `client_hint+title_key`.
- **Precision важнее recall на входе AI, но recall не ниже 1.00 на эталоне:** нужный заказ не должен отсекаться словами-исключениями.

**Не делает:** не оценивает шансы и цену (Analyst/Sales), не пишет клиентам, не подаёт ставки, не меняет статусы после NEW
(DIRECTOR runtime), не чинит сбои (GUARDIAN), не меняет свои настройки сам (их меняет владелец `/search_settings` [ПЛАН] или директор).

## 2. Входы
| Поле | Источник | Обяз. | Если нет |
|---|---|---|---|
| `title`, `description` (≤ 2000 знаков в фильтре) | API `projects/active` (`full_description=true`) | да | пустая строка → `no_keyword` (отсев) |
| `language` | API | да | не в `languages_csv` → отсев `language:<x>` |
| `type` | API (`fixed` / `hourly`) | да | иное/пусто → отсев (в Make обе ветки фильтра не проходят) |
| `budget.maximum`, `currency.exchange_rate` | API + курс EUR (`/currencies/`) | да | нет максимума → 0 € → отсев по бюджету |
| `bid_stats.bid_count` | API | нет | 0 |
| `id`, `seo_url`, `status`, `deleted`, `nonpublic`, `time_submitted` | API | да | без `id` дедуп невозможен → модуль 6 не находит ключ, проект не пишется |
| Запись `search` | `lh_settings` | да | значений по умолчанию в Make нет: GetRecord вернёт пусто → пустые `jobs[]`/regex → поведение фильтра непредсказуемо [ПРЕДПОЛОЖЕНИЕ]. Запись удалять нельзя; пустая `hb_note` «search v» — признак для GUARDIAN |
| Пересылка владельца (LH-03) | Telegram → LH-20 → LH-03 | — | текст без URL → лид без ссылки, Analyst ставит не выше COLD |

Настройки `search` (v2 в Make [ФАКТ], v3 — предложение [ПЛАН]): `jobs_csv`, `include_regex`, `exclude_regex`, `languages_csv`,
`budget_fixed_min_eur` (100), `budget_hourly_min_eur` (15), `max_bids` (200), `window_hours` (12), `max_per_run` (2), `send_grades_csv`.

## 3. Выходы
1. **Прошёл** → HTTP POST (form) в LH-03: `token`, `source=freelancer`, `source_url`, `text` → LH-03 создаёт лид:
   `lead_id = LH-YYYYMMDD-<6 hex>`, `status = NEW`, `url_hash`, `text_hash`, `title` (≤ 120), `found_at`; событие `LEAD_CREATED`.
   Запись `fl-<id>` в 205357: `status = sent_lh03`, `verification = "API: status=…, nonpublic=…, deleted=…; Gatekeeper ok (search v<N>)"`.
2. **Дубликат** (LH-03) → лид не создаётся, URL дописывается в `duplicates`, событие `DUPLICATE_DETECTED`, владельцу строка ♻️.
3. **Отсеян** → ничего не пишется, 0 операций (фильтр на связи). Причина в Make **не журналируется** (D12).
   [ПЛАН] счётчики `passed/seen` в `hb_lh01.hb_note` + статус `FILTERED_OUT` с причиной (как `reason` в `gate()`: `type:`, `language:`, `exclude:<слово>`, `no_keyword`, `budget<N>`, `bids>N`).
4. **Heartbeat** `hb_lh01`: `hb_at`, `hb_status = ok`, `hb_note = "scout run, search v<N>"` [ФАКТ]. Пишется **в начале** прогона
   (после чтения `search`), т. е. означает «запуск начался», а не «прошёл успешно» — GUARDIAN это учитывает.
Совместимость: формат POST в LH-03 и поля 205357 не меняются; новые поля только добавляются.

## 4. Правила (неизменные правила владельца)
- Ничего не отправлять клиентам и на площадку: ни сообщений, ни ставок. Только чтение публичного API.
- Не придумывать заказы, бюджеты, клиентов, ссылки: всё — из ответа API или пересылки владельца.
- Цены, платежи, ставки на площадке — не трогает вовсе.
- Секреты (`internal_token`, токены, URL вебхуков) — только в подключениях/настройках Make; не в логах, git, карточках.
- Ручная пауза владельца (`paused = true`): Scout продолжает собирать (лиды копятся в NEW), **не снимает паузу** и не обходит её.
- Новые источники (Upwork, Reddit, второй источник) — только после «да» владельца; категории «сайты» и «изготовление» — после Analyst v3.
- Изменение `search` в Make = изменение работающей логики → только решение директора + бэкап предыдущей записи (`search_prev`).

## 5. Неполные и спорные данные
- Нет бюджета / нет максимума / неизвестная валюта → 0 € → отсев (не угадываем бюджет).
- Язык вне списка → отсев; язык верный, но текст на другом → решает Analyst (`description_ru`), Gatekeeper не переводит.
- Тема неоднозначна (есть и include, и exclude) → **exclude важнее** (пример: «Telegram bot + SEO texts» → отсев).
- «claude/gpt/openai/llm» без признака разработки (bot, agent, automation, integration, api, workflow…) → не тема (v3).
- Ограничение по национальности/месту («仅限», «only chinese», «indian developers only», «local only») → отсев (v3).
  «nur deutschsprachig» **не** отсекается: владелец в Германии; иное — вопрос директору.
- Страна заказчика в API без авторизации пустая → не фильтруем по стране; в карточке «страна не подтверждена».
- Заявка, похожая на мошенничество, Gatekeeper не судит — это `risk_flags` Analyst.

## 10. Экономичность и версия
- Операции Make на запуск LH-01 ≈ **5 + 2 × (прошли фильтр) + 3 × min(новые, max_per_run)**; отсеянное = 0 операций.
  При 38 проектах/12 ч и 7 прошедших: ≈ 5 + 14 + 6 = **≈ 25 операций**; 4 запуска в сутки ≈ 100 кредитов/сутки. Токенов — 0.
- Каждый лишний пропуск стоит ≈ 3 операции + вызов Analyst (Haiku) — поэтому precision важнее объёма.
- Версия логики = `search.version` (v1 → v2 в Make 13.10 → v3 предложение). Откат: восстановить `search_prev` (1 запись, 0 правок сценария);
  откат сценария — `backup/7744024_before_2026-10-13.json`.
