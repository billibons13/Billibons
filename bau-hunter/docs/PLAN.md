Агенты 3 и 4 объединены в один вызов Sonnet ради кредитов (один прогон Sonnet через модуль Make ≈ 50–80 кредитов [ПРОВЕРЕНО по LH-11]).

### 1.1 Хранилища
- `bau_tenders` (новое, 512 КБ): одна запись = тендер/лот; поля: id, source, source_url, title, buyer_org, buyer_contact_org
  (только служебный контакт Vergabestelle), nuts, place, cpv[], deadline, est_value, procedure, prescore, score, grade,
  analysis_json, calc_json, risk_json, offer_json, status, status_at, created_at. Очистка через 60 дней (кроме WON).
- `bau_settings` (новое, 64 КБ): запись `main` (регион, CPV, ставки, пороги, лимиты) + `day_YYYY-MM-DD` (счётчики кредитов/вызовов).
- Лимит 10 МБ уже распределён → **освободить 1 МБ уменьшением maxSize** хранилищ с почти пустыми данными:
  «Klaus Affiliate — Produkte» (занято 2,5 КБ) и «TGBot Leads DE — Leads» (18,8 КБ) с 1 МБ до 512 КБ каждое. Данные не удаляются;
  RAIV_Fish и LH не трогаем. Это решение директора (не деньги, не удаление). [ПРОВЕРЕНО: размеры]

## 2. Telegram-пульт: отдельный бот (рекомендация)
**Отдельный бот «Bau-Pult» + сценарий BH-20**, а не Zulius:
1. У бота один webhook, он занят LH-20; чтобы кнопки Bau попадали куда нужно, пришлось бы менять LH-20 (148 КБ — только ручной импорт, T-0026).

3. BH-20 укладывается в < 45 КБ — генерируется и загружается инструментом.
4. Кредиты одинаковые; сам бот бесплатный.
Цена: владелец сам создаёт бота в @BotFather и вставляет токен в подключение Make (токен в чат не пишется).
Вариант Б (позже): объединить с Zulius, когда LH-20 будет разделён (T-0026, вариант 2).
Доступ — только owner chat_id из настроек + secret_token webhook (как LH-20).

## 3. Регион как настройка
`bau_settings.main.region_nuts` — список NUTS-кодов. По умолчанию Север: `DEF,DE6,DE5,DE9,DE8` (SH, HH, HB, NI, MV).
Команда `/region` переключает: «Север» / «Север + NRW» / «Вся Германия» (`DE`) / свой список. Доп. фильтр — `home_plz` + `radius_km`
(по PLZ места работ, если есть в объявлении; без геокодера — по первым цифрам PLZ, точность грубая [ПРЕДПОЛОЖЕНИЕ]).
Переход на всю Германию увеличит поток в ~4–6 раз [ПРЕДПОЛОЖЕНИЕ] → сначала пересчитать кредиты (этап 6).

## 4. SCORE
Шкала и механика — как LH: `score = round(10 × Σ wᵢ·sᵢ)`, sᵢ ∈ 0..10, Σw = 1, затем caps, затем grade
(HOT ≥ 80, WARM ≥ 60, COLD ≥ 40, иначе REJECT; пороги — в настройках).

| Ключ | Вес | Что оценивает | Кто считает |
|---|---|---|---|
| trade_fit | 0,20 | CPV/описание ↔ Gewerke владельца | pre: CPV; AI: текст |
| region_fit | 0,15 | NUTS/PLZ ↔ регион и радиус | без AI |
| size_fit | 0,15 | объём/стоимость лота ↔ мощность фирмы (min/max заказ) | pre + AI |
| deadline_fit | 0,12 | дней до срока подачи и до начала работ | без AI |
| margin_potential | 0,12 | ожидаемая маржа (после агента 3; до него = 5 «неизвестно») | AI + расчёт |
| requirements_fit | 0,07 | Eignung: PQ-VOB, референции, страховки, обороты | AI |
| docs_clarity | 0,08 | есть ли LV, понятны ли объёмы | AI |
| competition | 0,06 | тип процедуры (offen / beschränkt / Verhandlung), число лотов | pre |
| buyer_reliability | 0,05 | публичный заказчик (высоко) / частный | pre |

Caps: срок подачи < `min_days_to_deadline` (7) → ≤ 39; Gewerk не из списка → ≤ 39; NUTS вне региона → REJECT;
нет source_url → ≤ 59; требование, которого у фирмы нет (напр. PQ-VOB, если владелец указал «нет») → ≤ 59;
оценочная стоимость < `minimum_order_eur` → ≤ 59; risk_flags уровня «стоп» → ≤ 39. Причина — в `score_cap_reason`.
**Предварительный score (без AI)** = те же формулы, где AI-ключи = 5 («неизвестно»); в карточку попадают только prescore ≥ `card_threshold`.

## 5. Объёмы, стоимость, прибыль (агент 3) — метод и честные пределы
- **Цены не выдумываются.** Ставки владельца — входные параметры в `bau_settings`: `stundensatz_eur`, `rates_eur` (€/м², €/шт по позициям
  Gewerk), `material_markup_pct`, `travel_eur_per_km`, `overhead_pct`, `risk_reserve_pct`, `minimum_order_eur`.
  Нет ставки → позиция «UNKNOWN», цена не считается.
- Расчёт по каждой позиции: количество (с источником: «LV поз. 02.03» / «текст объявления» / «оценка AI — низкая точность»),
  ставка (источник: настройки владельца), сумма. Далее: Selbstkosten = Lohn + Material·(1+markup) + Fahrt + Gemeinkosten;
  Angebotspreis = Selbstkosten·(1+Wagnis+Gewinn); Gewinn = Angebotspreis − Selbstkosten. Арифметику считает Make (формулы), не Claude.
- Точность (указывается в карточке) [ПРЕДПОЛОЖЕНИЕ — проверить на этапе 3]:
  только текст объявления → «оценка не надёжна, ±50 % и хуже» либо «не оценить»; LV с количествами → ±15–25 % (зависит от ставок);
  без осмотра объекта — всегда оговорка.
- LV/документы скачивает **владелец** с платформы (там регистрация) и пересылает PDF/GAEB в пульт; автоматического входа на платформы нет.
  GAEB-разбор — отдельной задачей позже (теханализ).

## 6. Чек-лист рисков (агент 4)
Срок подачи / срок выполнения нереален · требуются PQ-VOB / сертификаты / референции, которых нет · Vertragsstrafe, Bürgschaften
(Vertragserfüllung 5 %, Mängelansprüche 3 %) · Nebenangebote запрещены / только Hauptangebot · большой объём > мощность фирмы ·
далеко от базы (Fahrtkosten, Unterkunft) · работы в эксплуатируемом здании (школа, больница — Arbeitszeiten, Sicherheit) ·
Schadstoffe (Asbest, PCB, KMF) в старом фонде · неясные объёмы / «nach Aufwand» · Lohngleitklausel / Tariftreue-Erklärung (Landesvergabegesetz:
SH, HH, HB, NI, MV — требования различаются) [ПРЕДПОЛОЖЕНИЕ] · субподряд разрешён/запрещён · платежи (Abschlagszahlungen) ·
одновременная загрузка (уже взятые заказы). Флаг «стоп» → cap ≤ 39; остальные — в карточку с объяснением.

## 7. КП и сообщение (агент 5) — правила
- Только **черновики**. В blueprints нет ни одного модуля отправки e-mail/сообщений третьим лицам — проверяется скриптом генератора.
- Для тендера: официальное Angebot = формуляры платформы (Angebotsschreiben, LV с ценами) — заполняет владелец. Агент 5 даёт:
  (1) краткое сопроводительное письмо/Anschreiben DE; (2) при неясностях — Bieterfrage DE через платформу; (3) перевод RU для владельца.
- Тон: деловой, Sie, без обещаний, которых нет в данных; цены — только из расчёта агента 3 с пометкой «на основе ставок владельца»;
  реквизиты фирмы — только из `bau_settings` (не выдумываются); дата и номер объявления обязательны.
- Кнопка «✍️ Открыть тендер» ведёт на source_url (страница объявления/платформы). Владелец отправляет сам.

## 8. Правовая рамка
- **DSGVO:** храним только служебные контакты, опубликованные в объявлении (организация, e-mail/телефон Vergabestelle). Имена
  сотрудников — не храним или удаляем через 60 дней вместе с записью. Основание — Art. 6 Abs. 1 lit. f (законный интерес). [ПРЕДПОЛОЖЕНИЕ, не юрконсультация]
  Заявки с сайта (7743356) — по согласию из формы; хранить по сроку из текста согласия.
- **UWG § 7:** рекламные письма без предварительного согласия — нельзя (по e-mail — и для B2B). Поэтому: нет авторассылок, нет
  холодных писем; ответ на тендер через платформу и Bieterfragen рекламой не являются [ПРЕДПОЛОЖЕНИЕ]. Всё отправляет владелец.
- **Источники:** только API/RSS/открытые данные; без логина, без обхода защит; соблюдаем условия сайтов и лицензии (TED, CC0).
- **Vergaberecht:** подача — по VOB/A через e-Vergabe; бот не подаёт ничего.

## 11. Что нужно от владельца
1. Gewerke (что фирма делает сама): напр. Trockenbau, Maler, Fliesen, Bodenbeläge, Sanitär/Badsanierung, Komplettrenovierung — список.
2. База: PLZ, радиус выезда (км), регион старта (по умолч. Север).
3. Мощность: человек в бригаде, мин. и макс. сумма заказа, сколько заказов параллельно.
4. Ставки: Stundensatz, €/м² (или €/шт) по основным позициям, наценка на материал, Fahrtkosten, накладные, резерв/прибыль %.
5. Данные фирмы для КП: название, Rechtsform, адрес, Handwerksrolle, USt-IdNr., страхование (Betriebshaftpflicht), PQ-VOB (да/нет), 3 референции.
6. Создать бота в @BotFather и вставить токен в подключение Make (сам).
