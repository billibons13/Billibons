## Что делает
1. Каждый день в 06:30 (Make: daily 06:30, nextExec 04:30 UTC = 06:30 CEST) [ПРОВЕРЕНО]. Что зимой останется 06:30 по Берлину (часовой пояс организации) — [ПРЕДПОЛОЖЕНИЕ].
2. HTTP POST `https://api.ted.europa.eu/v3/notices/search`, без ключа, JSON-тело: expert query
   `classification-cpv=45* AND place-of-performance IN (DEF DE6 DE5 DE9 DE8) AND publication-date=<вчера, Europe/Berlin>`,
   поля: publication-number, notice-title, buyer-name, buyer-city, deadline-receipt-tender-date-lot, estimated-value-lot,
   estimated-value-cur-lot, identifier-lot; limit 15. Запрос принят API (HTTP без ошибки, ключ не нужен) [ПРОВЕРЕНО].
3. Iterator → Text aggregator: нумерованный список (название DE, заказчик + город, Frist, стоимость если есть, число лотов если > 1,
   ссылка `ted.europa.eu/de/notice/-/detail/<номер>`). Текст обрезается до 3700 символов (лимит Telegram 4096); если найдено > 15 — строка «… ещё N».
4. chat_id владельца читается внутри Make из data store 207951 (lh_settings), запись `main` — как в LH; токен бота — в Telegram-подключении
   Make 9480305 (бот Zulius), как в LH. В репозитории нет ни chat_id, ни токена [ПРОВЕРЕНО grep].
   Если при генерации задан env `LH_OWNER_CHAT_ID`, дополнительно пишется `BH-01.local.json` (в .gitignore) с chat_id из env без чтения data store.
5. 0 объявлений → фильтр перед итератором, ничего не отправляется (1 кредит) [ПРЕДПОЛОЖЕНИЕ: по логике фильтра, отдельно не тестировалось].

Без своего data store, без AI, без кнопок. Получатель — только владелец.
