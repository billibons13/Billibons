# Claus Affiliate Hunter — регламент автономного запуска

Этот файл — инструкция для Claude, который запускается по расписанию (Routine) в свежей сессии
с этим репозиторием и подключением Make. Работай строго по шагам. Рабочая папка: `klaus-affiliate-hunter/`.

## Жёсткие правила (нарушать нельзя)
1. **Никогда не выдумывай партнёрскую ссылку, комиссию, цену, наличие или отзывы.** Ссылки строит только
   `python3 -m hunter link <url>` из данных `config.json`. Нет данных → статус `unverified`/`pending`, поле пустое.
2. Источники — только официальные страницы магазинов/брендов, открытые страницы партнёрских программ,
   официальные API и фиды. Не обходи логины, капчи, robots.txt, платёжные стены; не используй скрейперы
   Amazon (сторонние «Amazon scraper»-API нарушают Operating Agreement PartnerNet).
3. Наличие товара в магазине ≠ наличие партнёрской программы. Программа считается подтверждённой, только
   если она есть в `config.json` (Amazon tag / Awin `status: joined`).
4. Если подходящих новых товаров нет — ничего не отправляй и не придумывай. Пустой день — нормальный результат.
5. Цифры EPM/конверсии без фактических данных — только сценарии с пометкой `assumption: true`.
6. Медицинские, строительные и технические обещания — только из официальных данных производителя.
   Для биоцидов (средства от плесени) — правила BPR Art. 72 (см. `docs/COMPLIANCE.md`).
7. Не больше `max_new_products_per_day` новых товаров в день (config.json).
8. Не меняй Make-сценарии и не удаляй записи (кроме старых `klaus-scripts-*`, см. шаг 6) — только читай базу
   и отправляй данные через инструменты.

## Make (ID в config.json → `make`)
- База товаров: data store `203568` — читать `mcp__Make__data-store-records_list`.
- Отправка товара/статуса: инструмент `7712897` → `mcp__Make__scenarios_run` (`scenarioId: 7712897`,
  `responsive: true`, `data: {"target": "intake"|"status", "json": "<JSON одной строкой>"}`).
  Успех — `statusCode 200` и `"ok": true`; 400/404 — исправь данные, не повторяй вслепую.
- Отчёт владельцу в Telegram: инструмент `7713110` (`data: {"text": "..."}`, до 3500 знаков, без Markdown).

## Официальные API (если в config.json → make заполнены ID инструментов)
- `tool_amazon_searchitems` / `tool_amazon_getitems` — поиск и проверка товаров amazon.de (цена, наличие,
  продавец, рейтинг, ранг). `partner_tag` = `config.amazon_partner_tag`. Это основной источник данных Amazon.
- `tool_awin_programmes` — какие программы Awin реально `joined` (сверяй с `config.awin_programmes`;
  расхождения — в еженедельный отчёт, config сам не меняй).
- `tool_awin_link` — официальный tracking-link Awin; предпочтительнее, чем `hunter link` для Awin.
- `tool_awin_transactions` — продажи и комиссии за период → в Make через `target: "status"`
  (`sales`, `confirmed_commission_eur`, `refunds` по product_id, если транзакцию можно сопоставить с товаром).
- Ответ API с ошибкой авторизации (401/403) → отчёт владельцу, без повторов.

## Ежедневный цикл
1. **Состояние.** Выгрузи базу (limit 1000) в `/tmp/records.json`. Отдели записи `category = "_klaus_scripts"`
   (это недельные сценарии Klaus) от товаров. Список `product_id` товаров — для дедупликации.
2. **Сценарии Klaus.** Возьми самую свежую запись `klaus-scripts-*`, поле `notes` → `/tmp/scripts.txt`,
   выполни `python3 -m hunter match /tmp/scripts.txt`. Получишь типы товаров под каждый ролик
   (скрипты «nur Tipp» — без товаров). Это главный приоритет поиска на неделю.
3. **Поиск.** Для каждого нужного типа товара (сначала из шага 2, затем сезонные категории из
   `hunter/taxonomy.py`, у которых сейчас сезон) ищи кандидатов через WebSearch (обнаружение), а цену,
   наличие и продавца подтверждай в таком порядке:
   1) официальные API через Make-инструменты, если они перечислены в `config.json → make` (Amazon Creators API,
      Awin Product Feed / Publisher API);
   2) WebFetch страницы магазина/производителя, если сеть среды её пропускает (amazon.de не читать
      WebFetch'ем — данные Amazon только через Creators API);
   3) иначе цена/наличие остаются неподтверждёнными (`price_eur: null`, `availability: "unknown"`) —
      такой товар не может получить приоритет A и уходит в базу кандидатом.
   Что искать:
   - на amazon.de (если в config есть `amazon_partner_tag`) — страница товара `/dp/ASIN`, цена, наличие,
     продавец (предпочтительно «Verkauf und Versand durch Amazon» или известный бренд), рейтинг;
   - в магазинах программ Awin из `config.awin_programmes` со статусом `joined`;
   - новинки и растущий спрос: разделы «Neuheiten», «Bestseller», сезонные подборки магазинов.
   Отбрасывай: подделки/no-name без немецкого импортёра, без CE для электротоваров, без доставки в DE,
   сомнительные характеристики, запрещённые/опасные товары, дубликаты из шага 1.
4. **Проверка и оценка.** Для каждого кандидата:
   `python3 -m hunter link <product_url>` → affiliate_url/статус/cookie. Собери кандидатов в
   `/tmp/candidates.json` (`[{"product": {...}, "signals": {"demand":0..1, "competition":0..1, "video_fit":0..1}}]`).
   Сигналы ставь честно и кратко обоснуй в `notes` (например: «Bestseller-Rang 1.200 in Baumarkt, 4,5★/3.100;
   Saison Okt–Mär»). Заполни `video_category`, `matching_klaus_scenario` (заголовок ролика из шага 2),
   `video_hook` (немецкий, без обещаний, которых нет у производителя), `verification_date` = сегодня,
   `source_url`. Выполни `python3 -m hunter prepare /tmp/candidates.json --stats /tmp/records.json`.
5. **Передача в Make.** Каждый объект из `ready` (кроме тех, что уже есть в базе с тем же `product_id` и без
   изменений цены/наличия) отправь `target: "intake"`. Make сам: проверит, сохранит, поставит A/B в очередь
   Klaus и пришлёт владельцу уведомление о новом товаре в очереди.
6. **Проверка ссылок и цен** (товары с `content_queue = true` или `video_status` ∈ queued/in_production/published):
   открой `product_url`; если страница исчезла/товар снят → `target: "status"`, `{"product_id", "link_status": "broken"}`;
   нет в наличии → `"availability": "out_of_stock"`; цена изменилась → `"price_eur"`; всё в порядке →
   `"link_status": "ok"`, `"verification_date"`. Записи `klaus-scripts-*` старше 8 недель удали
   (`mcp__Make__data-store-records_delete`) — база ограничена 1 МБ.
7. **Дневной отчёт** — только если что-то произошло (новые товары, снятые с очереди, ошибки).
   Иначе ничего не отправляй.

## Еженедельно (понедельник)
- `python3 -m hunter learn /tmp/records.json` → какие категории дают клики/продажи (по факту).
- Отчёт в Telegram: новые товары за неделю (A/B/C/HOLD), очередь Klaus, опубликованные ролики, клики,
  продажи, подтверждённые комиссии, лучшие/худшие категории (только с `enough_data`), товары в HOLD,
  которым не хватает партнёрской программы (какую программу стоит подключить).
- Поиск новых партнёрских программ для DE в категориях Klaus (Awin, Adcell, Belboon, TradeTracker,
  программы производителей): условия, комиссия, cookie, правила соцсетей. В отчёт — только проверенное
  по официальным страницам, с ссылками; решение о подключении принимает владелец.

## Ежемесячно (1-е число)
- Пересмотр категорий: где фактический EPM выше/ниже, какие сезоны впереди, предложения по новым категориям
  (в духе Klaus). Отправь владельцу как предложение — `hunter/taxonomy.py` не меняй без его одобрения.

## Если что-то не работает
- Make-инструмент вернул ошибку → один повтор; затем короткий отчёт владельцу с текстом ошибки.
- Нет данных аккаунтов в config.json → товары остаются кандидатами (HOLD), в еженедельном отчёте
  напомни, каких данных не хватает.
