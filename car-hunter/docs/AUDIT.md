**Мнение аудитора.** Ровно пять агентов — у наборов A и B. Поскольку владелец просит аудит **существующей** системы,
вероятнее всего имеется в виду **A — 5 агентов Lead Hunter** (они реально работают в Make и в боте Zulius).
Набор B — та же схема, только для тендеров (ещё не построена). Новый модуль Car Hunter стоит строить **по схеме,
общей для A и B**: поиск → фильтр + SCORE → оценка/расчёт → риски → черновик сообщения, карточка в Telegram.
Директор считает более вероятным набор B; это расхождение остаётся **открытым вопросом владельцу** (§9, вопрос 1).

- Фильтр: `hu_months_left = (ГГГГ×12 + ММ) − (текущий ГГГГ×12 + ММ)`; «Neu» → 24; поле пустое → `unknown` (не отбрасывать, а
  ограничить score и пометить «проверить HU»). Порог `tuv_min_months` в настройках (например 12).
- Есть ли на mobile.de фильтр «HU mind. X Monate» в самом поиске — не подтверждено [ПРЕДПОЛОЖЕНИЕ]; поэтому фильтр HU делаем у себя.

### 6.3 Цена и пробег
Задаются **в самом сохранённом поиске** (Preis bis, Kilometer bis, Erstzulassung ab, Kraftstoff, Umkreis um PLZ) —
это сокращает поток писем; у себя — повторная проверка и SCORE [ПРЕДПОЛОЖЕНИЕ по стандартным фильтрам порталов].

### 6.4 Право
- **Не скрейпить**, не ходить за логин, не обходить защиту; брать только то, что платформа сама прислала владельцу (письмо). [ПРОВЕРЕНО по общей практике: BGH I ZR 224/12; EuGH C-30/14 Ryanair — договорные ограничения баз данных; ПРЕДПОЛОЖЕНИЕ для конкретных AGB]
- **DSGVO**: контакты частных продавцов не сохранять в базе дольше нужного; хранить ссылку на объявление, а не телефон/имя;
  удаление через N дней после закрытия. Покупатель-частник для своей покупки, скорее всего, под «Haushaltsausnahme»
  Art. 2 Abs. 2 lit. c; если модуль станет услугой для клиентов — нужны Art. 6 Abs. 1 lit. b/f, Art. 13/14 [ПРОВЕРЕНО: текст DSGVO; применимость — ПРЕДПОЛОЖЕНИЕ].
- **UWG / письма продавцам**: никаких автоматических сообщений продавцам; черновик (`dealer_draft`) отправляет только владелец вручную (как в LH).

## 7. ПЛАН: как добавить Car Hunter, не ломая архитектуру

### 7.1 Принципы
1. Ничего из существующего не меняем на первых этапах: **отдельные сценарии CH-xx, отдельная папка Make, отдельное хранилище**.
2. Схема как в LH/BH: **приём → детерминированный фильтр + SCORE (без AI) → карточка в Telegram с кнопками → AI только по кнопке**.
3. Все пороги — в настройках (как `lh_settings.main`), не в коде. Промты — файлы `car-hunter/agents/*.md` с версией; генератор
   `car-hunter/scripts/generate_ch.py`, blueprint < 45 КБ, эталон скоринга `scoring_car.py` с тестами.
4. Клиентам/продавцам ничего не уходит автоматически.

### 7.2 Источники (стратегия)
- **MVP (рекомендуется):** владелец создаёт сохранённые поиски на mobile.de и AutoScout24 с e-mail-уведомлением на свой Gmail →
  фильтр Gmail «от mobile.de/AutoScout24 + тема Suchauftrag» → **автопересылка на mailhook Make** (адрес вида `…@hook.eu1.make.com`).
  Плюсы: нет пароля Google в Make, нет опроса почты (кредиты тратятся только при приходе письма), легально (письмо адресовано владельцу).
  Подтверждение адреса пересылки Gmail приходит в очередь mailhook — код виден в Make [ПРЕДПОЛОЖЕНИЕ, проверить на этапе 1].
- **Вариант Б (без Make):** Gmail → пересылка на адрес Cloudflare Email Routing → Email Worker (postal-mime) парсит и шлёт в Make/Telegram.
  Почти бесплатно, но нужен свой домен в Cloudflare [ПРОВЕРЕНО: Cloudflare changelog Email Routing; домен владельца — неизвестно].
- **Вариант В:** ручная пересылка ссылки объявления в бот (как LH-03): ссылка → карточка; данные из текста, который владелец вставил.
- **Вариант Г:** mobile.de Search-API — только если у владельца есть дилерский аккаунт и разрешение mobile.de.
- Не используем: скрейпинг mobile.de / AutoScout24 / Kleinanzeigen, сторонние скрейперы.

### 7.3 Сценарии (предложение)
```
Gmail-фильтр ─► mailhook ─► CH-01 Intake (парсинг письма → N объявлений, нормализация, дедуп по url/listing_id,
                                       HU-месяцы, пробег, цена, PLZ → ch_vehicles NEW, pre-score)
                                   └─► карточки топ-N в бот (лимит в день)
Ссылка в бот ─────────────────────► CH-03 Manual Intake (как LH-03)
Кнопки карточки ───────────────────► CH-20 пульт (✅ Интересно / ❌ Нет / ⭐ / 🔍 Анализ / ✉️ Черновик продавцу)
🔍 Анализ ─────────────────────────► CH-10 (Claude Haiku: риски по описанию, честность цены, вопросы продавцу) — только по кнопке
✉️ Черновик ───────────────────────► CH-11 (Haiku/Sonnet: письмо продавцу DE, Sie) — отправляет владелец сам
```

но кнопки придут в LH-20 → нужна маленькая ветка «ch:» в LH-20 (как сделано для AI-01) — менять LH-20 только после
завершения T-0034. Решение — владелец.

### 7.9 Стоимость [ПРЕДПОЛОЖЕНИЕ — оценка]
- Приём: 1 письмо ≈ 5–15 операций (mailhook, парсер, итератор, поиск дубля, запись, отправка карточки) → 2 письма/день ×
  2 портала ≈ 300–900 кредитов/мес. Можно уменьшить: парсить в Cloudflare Worker (вариант Б), в Make — только запись и карточка.
